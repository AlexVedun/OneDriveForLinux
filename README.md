# OneDrive для Linux

Разработка по [плану](onedrive-linux-plan.md). Реализованы каркас и основа
режима только чтения: каталог SQLite, чтение страниц `delta` и скачивание
выбранного файла. Для этапа 2 добавлены выбор локальной папки, безопасное
сканирование и предварительный план по трём состояниям. Обычный режим пока
только показывает план и не выполняет двустороннюю синхронизацию.

## Разработка на Fedora 44

```sh
sudo dnf install rust cargo rustfmt clippy gcc pkgconf-pkg-config gtk4-devel libadwaita-devel
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo test -p onedrive-catalog
cargo build -p onedrive-daemon
dbus-run-session -- sh scripts/smoke-dbus.sh
```

## Тестовая регистрация Microsoft

В [Microsoft Entra App registrations](https://learn.microsoft.com/en-us/entra/identity-platform/quickstart-register-app)
создайте приложение для личных аккаунтов Microsoft. В разделе Authentication
добавьте платформу **Mobile and desktop applications** с URI
`http://localhost/callback`. В API permissions добавьте делегированные
`Files.ReadWrite` и `offline_access`. Клиентский секрет не создавайте.

Создайте файл `.env` в корне проекта и укажите в нём Application (client) ID:

```sh
ONEDRIVE_CLIENT_ID=ваш-client-id
```

Файл `.env` исключён из Git. Демон читает его из текущей директории при
запуске; переменная окружения `ONEDRIVE_CLIENT_ID`, если задана, имеет
приоритет. Для проверки входа нужен работающий Secret Service (например,
GNOME Keyring или KWallet).
Токены в файлы проекта и журнал не пишутся.

В первом терминале с пользовательской шиной D-Bus запустите демон:

```sh
cargo run -p onedrive-daemon
```

Во втором терминале запустите интерфейс:

```sh
cargo run -p onedrive-desktop
```

Окно запрашивает `Status` у фонового процесса. Кнопка входа открывает системный
браузер; демон проверяет `state`, обменивает код с PKCE, проверяет доступ к
`/me/drive` и сохраняет refresh token в системном хранилище секретов.
После входа кнопка «Проверить OneDrive» получает дерево. Дальнейшие изменения
проверяются каждые пять минут или по этой кнопке. Кнопка «Обновить список»
перечитывает локальный каталог, а «Скачать выбранный файл» предлагает путь
сохранения. База находится в `$XDG_STATE_HOME/onedrive-linux/catalog.sqlite3`
(по умолчанию `~/.local/state/onedrive-linux/catalog.sqlite3`).

Кнопка «Папка синхронизации» сохраняет локальный путь в
`$XDG_STATE_HOME/onedrive-linux/sync.sqlite3`. «План синхронизации» сканирует
папку без перехода по символическим ссылкам и показывает предложения по
загрузке, скачиванию и конфликтам. Он только показывает план; файлы не
изменяются. При первом сопоставлении файлы с одинаковым путём считаются
конфликтом, пока нет подтверждённой связи. Смена папки блокируется, если в
базе уже есть связи или операции в очереди.
Однозначное переименование показывается одной операцией с исходным и новым
путём. Локальное переименование требует подтверждения; изменение содержимого
одновременно с удалённым переименованием считается конфликтом. Выполнение
переименований пока не подключено.
Очередь хранит требующие решения операции отдельно: удаления и удалённые
переименования нельзя выдать исполнителю до явного подтверждения, а конфликт
нельзя превратить в действие простым подтверждением. `SyncReviewCount()`
показывает число таких записей через D-Bus. Интерфейс подтверждения ещё не
подключён.

Без тестовой регистрации можно запускать все тесты каталога и скачивания:
они используют локальные ответы Graph и временные файлы. После `410 Gone`
каталог сохраняется для сверки, а статус становится `reconciliation-needed`.
При недоступной шине или процессе окно сообщает `daemon-unavailable`.

Для разработки загрузки реализованы D-Bus методы `QueueUploadChanged(item_id)`,
`QueueUploadNew(path)` и `RunQueuedUpload()`. Новый файл пока можно поставить в
очередь только в корне синхронизации; пустые файлы и создание родительских
каталогов ещё не поддерживаются. Метод выполнения выключен,
пока фоновый процесс не запущен с `ONEDRIVE_EXPERIMENTAL_UPLOAD=1`.
Для существующего файла используется `If-Match`. Передача идёт фрагментами
по 5 МиБ и сохраняет сеанс в защищённой SQLite-базе. После обрыва следующий
запуск запрашивает у сервера смещение.
Для нового файла Graph получает `conflictBehavior: fail`, чтобы занятое имя
привело к конфликту, а не к перезаписи.
Методы `SetSyncPaused(bool)` и `SyncPaused()` сохраняют паузу очереди между
запусками: новые операции не выдаются исполнителю, а уже начатая передача
завершается. Эта настройка пока доступна через D-Bus; автоматический запуск
очереди ещё не реализован.
Этот путь не проходил проверку с живым аккаунтом Microsoft и пока не включён
в обычный интерфейс.

Для будущего виртуального диска понадобятся `fuse3 fuse3-devel`. AppImage
также требует отдельного инструмента упаковки и проверки на целевых системах.
