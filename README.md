# OneDrive для Linux

Разработка по [плану](onedrive-linux-plan.md). Реализованы каркас и основа
режима только чтения: каталог SQLite, чтение страниц `delta` и скачивание
выбранного файла. Для этапа 2 добавлены выбор локальной папки, безопасное
сканирование и предварительный план по трём состояниям. Обычный режим пока
только показывает план и не выполняет двустороннюю синхронизацию.

Для будущего виртуального диска добавлен `onedrive-cache`: он сохраняет целый
файл по ID диска, ID файла и версии, проверяет ожидаемый размер, атомарно
публикует копию и ограничивает объём, вытесняя давно не использованные файлы.
Закреплённые копии сохраняются при очистке; после прерывания записи кэш
удаляет незарегистрированные временные файлы при следующем открытии.

`onedrive-mount` строит из локального каталога дерево для чтения: проверяет
родительские связи, имена и размеры, предоставляет `lookup`, `getattr` и
`readdir`, сохраняет inode при переименовании файла. Дерево создаётся только
из полного каталога активного диска, а чтение файла по смещению использует
версионный кэш. Перед будущим монтированием проверяются пересечения путей,
пустота точки монтирования, её занятость и доступность `/dev/fuse`.
FUSE-адаптер реализует чтение дерева и файлов, а изменения существующих файлов
сохраняет в локальных черновиках. При промахе кэша во время чтения он обращается
к загрузчику. Демон монтирует и размонтирует виртуальный диск
через D-Bus `MountVirtualDrive(absolute_path)` и `UnmountVirtualDrive()`;
`VirtualMountPath()` возвращает текущую точку или пустую строку. Точка должна
быть пустым каталогом вне папки синхронизации и кэша. При отсутствии `/dev/fuse`
вызов монтирования возвращает ошибку; обычная синхронизация остаётся доступна.
Если соединение пропало, уже сохранённые версии продолжают читаться из кэша.
Для отсутствующего файла FUSE возвращает сетевую ошибку (`ENETDOWN`), а окно
показывает состояние «Нет соединения» после ошибки передачи.
В окне кнопка «Подключить виртуальный диск» предлагает выбрать существующую
пустую папку; рядом отображается текущая точка и кнопка отключения. Для
проверки на реальной системе сначала войдите в OneDrive и дождитесь полного
обновления каталога, затем выберите точку монтирования. Изменения существующих
файлов пока остаются локальными; окно показывает их количество, состояния первых
трёх черновиков (сначала требующих внимания) и сообщает, что отправка в OneDrive
ещё не включена. Состояния основаны на локальном каталоге и могут устареть до
следующего обновления. Создание, удаление и переименование файлов
через виртуальный диск пока недоступны. Выбранный в списке файл можно сохранить
для доступа офлайн: приложение сначала загружает его текущую версию, затем
закрепляет копию в кэше. Снятие закрепления разрешает дальнейшее вытеснение,
но не удаляет файл сразу. Состояние выбранного файла показано рядом с кнопкой.
Лимит кэша задаётся в окне от 0,25 до 64 ГиБ и сохраняется между запусками.
При уменьшении лимита удаляются только незакреплённые копии; значение ниже
суммарного размера закреплённых файлов отклоняется.
Метод D-Bus `PrepareVirtualFile(item_id)` по запросу скачивает недостающий файл
после проверки `eTag` и размера до и после передачи; затем публикует его в
кэше с начальным лимитом 1 ГиБ. Он возвращает `cached` или `downloaded`.

## Разработка на Fedora 44

```sh
sudo dnf install rust cargo rustfmt clippy gcc pkgconf-pkg-config gtk4-devel libadwaita-devel
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo test -p onedrive-catalog
cargo test -p onedrive-cache
cargo test -p onedrive-mount
cargo build -p onedrive-daemon
dbus-run-session -- sh scripts/smoke-dbus.sh
cargo build -p onedrive-desktop
dbus-run-session -- sh scripts/smoke-tray.sh
```

## Тестовая регистрация Microsoft

В [Microsoft Entra App registrations](https://learn.microsoft.com/en-us/entra/identity-platform/quickstart-register-app)
создайте приложение для личных аккаунтов Microsoft. В разделе Authentication
добавьте платформу **Mobile and desktop applications** с URI
`http://localhost/callback`. В API permissions добавьте делегированные
`Files.ReadWrite` и `offline_access`. Клиентский секрет не создавайте.

Создайте файл `.env` в корне проекта и укажите в нём Application (client) ID:

```sh
ONEDRIVE_CLIENT_ID=ваш-client-id
```

Файл `.env` исключён из Git. Демон читает его из текущей директории при
запуске; переменная окружения `ONEDRIVE_CLIENT_ID`, если задана, имеет
приоритет. Пустое значение переменной явно отключает чтение ID из `.env`;
так запускаются локальные D-Bus тесты. Для проверки входа нужен работающий
Secret Service (например, GNOME Keyring или KWallet).
Токены в файлы проекта и журнал не пишутся.

В первом терминале с пользовательской шиной D-Bus запустите демон:

```sh
cargo run -p onedrive-daemon
```

Во втором терминале запустите интерфейс:

```sh
cargo run -p onedrive-desktop
```

Окно запрашивает `Status` у фонового процесса. Кнопка входа открывает системный
браузер; демон проверяет `state`, обменивает код с PKCE, проверяет доступ к
`/me/drive` и сохраняет refresh token в системном хранилище секретов.
После входа кнопка «Проверить OneDrive» получает дерево. Дальнейшие изменения
проверяются каждые пять минут или по этой кнопке. Кнопка «Обновить список»
перечитывает локальный каталог, а «Скачать выбранный файл» предлагает путь
сохранения. База находится в `$XDG_STATE_HOME/onedrive-linux/catalog.sqlite3`
(по умолчанию `~/.local/state/onedrive-linux/catalog.sqlite3`).

Кнопка «Папка синхронизации» сохраняет локальный путь в
`$XDG_STATE_HOME/onedrive-linux/sync.sqlite3`. «План синхронизации» сканирует
папку без перехода по символическим ссылкам и показывает предложения по
загрузке, скачиванию и конфликтам. Он только показывает план; файлы не
изменяются. При первом сопоставлении файлы с одинаковым путём считаются
конфликтом, пока нет подтверждённой связи. Смена папки блокируется, если в
базе уже есть связи или операции в очереди.
Фоновый процесс наблюдает за выбранной папкой через Linux inotify, включая
вновь созданные подкаталоги. `LocalChangeEpoch()` через D-Bus увеличивается
после локальных событий и при повторной установке наблюдения. События служат
сигналом для полной сверки: автоматическая постановка изменений в очередь
пока не подключена.
Однозначное переименование показывается одной операцией с исходным и новым
путём. Переименование в OneDrive требует подтверждения; изменение содержимого
одновременно с удалённым переименованием считается конфликтом.
Очередь хранит требующие решения операции отдельно: удаления и удалённые
переименования нельзя выдать исполнителю до явного подтверждения, а конфликт
нельзя превратить в действие простым подтверждением. `SyncReviewCount()`
показывает число таких записей через D-Bus. `QueueReviewActions()` добавляет
удаления и переименования в OneDrive из полного предварительного плана; метод
не делает сетевых запросов и не выполняет операции. `ReviewOperations()`
возвращает JSON с ID очереди, типом, исходным и целевым путём, удалённым ID,
ожидаемым `eTag` и признаком возможности подтверждения. `ApproveOperation(id)`
подтверждает только одну операцию удаления или переименования, а
`DismissOperation(id)` отклоняет одну ожидающую операцию. Конфликт можно только
отклонить; его разрешение требует отдельного действия. Кнопка «Рассмотреть
изменения» обновляет план, открывает сохранённую очередь и позволяет отдельно
подтвердить или отклонить каждую запись. При недоступном каталоге сохранённая
очередь остаётся доступной. Подтверждение сохраняет решение, но не запускает
исполнение операции.
Кнопка «Приостановить синхронизацию» сохраняет паузу в SQLite и запрещает
новые захваты операций из очереди; уже начатая операция может завершиться.
Кнопка меняется на «Возобновить синхронизацию» после подтверждения демоном.
«Обновить список» также перечитывает состояние паузы, в том числе после
изменений через D-Bus или перезапуска приложения.
Кнопка «Очередь и история» показывает ожидающие, заблокированные и последние
завершённые операции вместе с числом попыток и сохранённой причиной ошибки.
`OperationHistory()` возвращает через D-Bus общее число записей и до 200
операций, сначала заблокированные и ожидающие. Адреса сеансов загрузки и
локальные отпечатки через этот метод не выдаются.
Окно обновляет состояние демона каждые десять секунд. При переходе к ошибке,
отсутствию сети, необходимости входа или сверки либо потере связи с демоном
приложение отправляет системное уведомление. Повторный опрос не создаёт новые
уведомления о том же состоянии. Закрытие окна скрывает его и оставляет
приложение работающим для уведомлений; повторный запуск ярлыка открывает окно.
Кнопка «Выход» завершает только интерфейс, фоновый демон продолжает работу.
Индикатор StatusNotifierItem показывает состояние, стандартную системную
иконку и подсказку. Нажатие на него открывает окно; меню DBusMenu позволяет
открыть окно, папку синхронизации или очередь, приостановить либо возобновить
синхронизацию, проверить OneDrive и выйти. Открытие папки доступно после её
выбора, пока сохранённый путь ведёт к той же существующей директории. Пункт
паузы недоступен без связи с демоном. Рядом с очередью меню показывает число
ожидающих, выполняемых и заблокированных операций; завершённые и отклонённые
не учитываются. Демон отдаёт точное число через `SyncOutstandingCount()`.
Индикатор регистрируется у хоста `org.kde` или `org.freedesktop`, если тот
доступен. При отсутствии хоста приложение остаётся доступным через ярлык.
Проверка `smoke-tray.sh`
запускает интерфейс с пустым временным состоянием и отключённым client ID на
локальном headless Broadway display; для неё нужен `gtk4-broadwayd`.
`RunQueuedRemoteRename()` выполняет одно подтверждённое переименование или
перемещение файла при `ONEDRIVE_EXPERIMENTAL_UPLOAD=1`. Перед запросом метод
сверяет локальный отпечаток и единственность файла, сохранённую связь по ID,
исходный путь и `eTag` в полном каталоге, родительский ID назначения и занятость
имени. Graph повторно проверяется перед `PATCH`, который отправляется с
`If-Match`; ответ должен содержать ожидаемые ID, имя, родительский ID и новый
`eTag`. При сомнительном ответе операция останавливается для сверки. После
успеха нужно вызвать `RefreshCatalog()` для обновления локального каталога.
Проверки с живым аккаунтом пока не было.
`RunQueuedRemoteDelete()` выполняет одно подтверждённое удаление файла в
OneDrive при `ONEDRIVE_EXPERIMENTAL_UPLOAD=1`. Оно требует прежний путь,
подтверждённую связь по ID и `eTag`, отсутствие локального файла при сохранённом
обычном родительском каталоге. Перед `DELETE` Graph повторно сверяет ID, имя,
родителя и версию; запрос использует `If-Match`. Успешный ответ удаляет связь
из SQLite и требует `RefreshCatalog()` для обновления каталога. Graph помещает
удалённый таким запросом элемент в корзину OneDrive. Живой аккаунт пока не
проверен.
`RunQueuedLocalDelete()` выполняет одно подтверждённое локальное удаление при
`ONEDRIVE_EXPERIMENTAL_DOWNLOAD=1`. Перед переносом сверяются полный каталог,
удалённый ID, сохранённая связь, версия и отпечаток локального файла. Файл
атомарно переносится в закрытую папку
`$XDG_STATE_HOME/onedrive-linux/deleted-files/` под именем ID операции; повторный
запуск может завершить запись в SQLite после прерывания между переносом и
коммитом. Сохранённые файлы остаются доступны для ручного восстановления.
Если каталог синхронизации и каталог состояния находятся на разных файловых
системах, операция блокируется без изменения файла: атомарный перенос между
ними невозможен.

Без тестовой регистрации можно запускать все тесты каталога и скачивания:
они используют локальные ответы Graph и временные файлы. После `410 Gone`
каталог сохраняется для сверки, а статус становится `reconciliation-needed`.
При недоступной шине или процессе окно сообщает `daemon-unavailable`.

Для разработки загрузки реализованы D-Bus методы `QueueUploadChanged(item_id)`,
`QueueUploadNew(path)` и `RunQueuedUpload()`. Новый файл пока можно поставить в
очередь в корне или внутри уже существующих удалённых каталогов. Путь к
родителям проверяется по полному каталогу с учётом регистра; пустые файлы и
создание отсутствующих каталогов ещё не поддерживаются. Метод выполнения выключен,
пока фоновый процесс не запущен с `ONEDRIVE_EXPERIMENTAL_UPLOAD=1`.
Для существующего файла используется `If-Match`. Передача идёт фрагментами
по 5 МиБ и сохраняет сеанс в защищённой SQLite-базе. После обрыва следующий
запуск запрашивает у сервера смещение.
Для нового файла Graph получает `conflictBehavior: fail`, чтобы занятое имя
привело к конфликту, а не к перезаписи.
`QueueSafeUploads()` повторно сканирует локальную папку и ставит в очередь
только безопасные загрузки из полного предварительного плана. Метод возвращает
число новых ожидающих операций; повторный вызов не создаёт дубликатов.
Пустые локальные файлы явно указаны в списке пропусков и не превращаются в
запрос на удаление. Этот метод не выполняет сетевых запросов.
`QueueSafeDownloads()` ставит в очередь входящие файлы только из полного
каталога с `eTag`: родительский каталог уже должен существовать локально, а
путь назначения не должен быть занят каталогом или ссылкой. Повторный вызов
не создаёт дубликатов. `RunQueuedDownload()` выполняет одну операцию из этой
очереди при `ONEDRIVE_EXPERIMENTAL_DOWNLOAD=1`; в обычном режиме выполнение
отключено. Передача проверяет `eTag` и размер до и после скачивания, а также
повторно проверяет локальный файл перед заменой. Неожиданное изменение ставит
операцию на рассмотрение и сохраняет имеющийся локальный файл. Ручное
скачивание через `DownloadItem` остаётся отдельной операцией.
`QueueSafeLocalRenames()` ставит в очередь переименования из полного предварительного
плана, когда путь назначения свободен; повторный вызов не создаёт дубликатов.
`RunQueuedLocalRename()` применяет одну запланированную смену имени или пути
удалённого файла при `ONEDRIVE_EXPERIMENTAL_DOWNLOAD=1`. Перед переносом метод
сверяет ID, путь и `eTag` с полным каталогом, а также исходный путь и отпечаток
файла с сохранённой базой. Ссылки и занятое имя назначения блокируют операцию;
после прерывания между переносом и записью в SQLite повторный запуск распознаёт
уже перенесённый файл по содержимому.
`PrepareLocalFolders()` создаёт каталоги из полного удалённого дерева перед
постановкой скачиваний в очередь. Метод возвращает JSON со списками созданных
путей и пропущенных ID; ссылки, занятые файлы, несовпадения регистра и
неоднозначные удалённые имена не обходятся и не заменяются. Повторный вызов
не создаёт лишних каталогов.
`QueueSafeRemoteFolders()` сканирует локальные каталоги и ставит в очередь
создание только тех, чей родитель уже однозначно найден по ID в полном каталоге
OneDrive. Каталоги с конфликтом имени или регистра пропускаются. Вложенные
каталоги можно поставить в очередь после подтверждения созданного родителя и
обновления каталога. Метод не делает сетевых запросов. `RunQueuedRemoteFolder()`
выполняет одну такую операцию при `ONEDRIVE_EXPERIMENTAL_UPLOAD=1`: повторно
сверяет локальный каталог, удалённый родительский ID и занятость имени, затем
создаёт папку с `conflictBehavior: fail`. Конфликт или сомнительный ответ
останавливает операцию для сверки. После успешного создания требуется обновить
каталог через `RefreshCatalog()`, чтобы следующие вложенные папки получили
подтверждённый ID родителя. Живой Graph ещё не проверен.
Методы `SetSyncPaused(bool)` и `SyncPaused()` сохраняют паузу очереди между
запусками: новые операции не выдаются исполнителю, а уже начатая передача
завершается. Эта настройка пока доступна через D-Bus; автоматический запуск
очереди ещё не реализован.
Этот путь не проходил проверку с живым аккаунтом Microsoft и пока не включён
в обычный интерфейс.

Для монтирования виртуального диска нужен доступ к `/dev/fuse`; в окружении без
права прямого монтирования также нужен `fusermount3` из пакета `fuse3`.
Окно показывает доступность устройства и помощника до подключения. Метод
`VirtualFuseDiagnostics()` возвращает состояние устройства и наличие помощника;
отсутствие помощника само по себе не запрещает прямое монтирование.
`fuser` собирается без `fuse3-devel`. AppImage также требует отдельного
инструмента упаковки и проверки на целевых системах.
Демон записывает точку виртуального диска в `XDG_STATE_HOME/onedrive-linux/virtual-mount-path`.
Если после аварийного завершения она остаётся занятой, окно покажет путь и
запретит новое подключение. Проверьте его через `findmnt --target ПУТЬ` и,
если это прежний виртуальный диск, отключите `fusermount3 -u ПУТЬ`.
Демон не отключает занятую точку автоматически, чтобы не затронуть другое
монтирование. После освобождения точки устаревшая запись удалится при
следующем запросе состояния.
На Linux-хосте с доступным FUSE можно проверить чтение и сетевую ошибку без аккаунта:

```sh
ONEDRIVE_FUSE_SMOKE=1 cargo test -p onedrive-mount mounted_tree_reads_cached_file_without_network
```

Приватное хранилище черновиков сохраняет изменения через FUSE отдельно от кэша
и подтверждает запись только после `fsync`. Черновик хранит ID файла и исходный
eTag для последующей проверки конфликта и переживает перезапуск процесса.
Полная замена содержимого может начаться офлайн без загрузки прежней версии;
частичное изменение незакэшированного файла требует исходные байты.
Автоматическая отправка черновиков в OneDrive пока не подключена. Метод `VirtualDrafts()` возвращает
состояние каждого черновика относительно локального каталога; совпадение eTag
в этом списке не заменяет повторной проверки удалённой версии перед отправкой.
Экспериментальный метод `RunVirtualDraftUpload(item_id)` доступен только при
`ONEDRIVE_EXPERIMENTAL_VIRTUAL_UPLOAD=1`. Он отправляет один непустой черновик
после отключения виртуального диска и при отсутствии настроенной папки
синхронизации, предварительно проверяет живую
версию в Graph и сохраняет новые локальные правки, возникшие во время отправки.
Автоматическая очередь, возобновление upload session после перезапуска и
пустые файлы пока не реализованы. Метод не проверялся с живым аккаунтом.

```sh
ONEDRIVE_FUSE_SMOKE=1 cargo test -p onedrive-mount writable_mount_persists_truncating_replacement
```
